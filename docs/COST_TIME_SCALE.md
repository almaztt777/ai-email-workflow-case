# Стоимость, экономия времени и 10 000 писем в день

## Стоимость одного прогона

В текущей версии V1 и V2 разбор делает обычный код, без платных запросов к AI API.

Поэтому дополнительная стоимость обработки сейчас:

- 1 письмо — **$0**;
- 100 писем — **$0**.

Если в дальнейшем добавить AI API для сложных случаев, стоимость уже нужно считать по фактическому количеству запросов и токенов.

## Сколько времени экономит на 100 письмах

Для оценки взял примерно 1 минуту ручной работы на одно короткое письмо: открыть, прочитать, найти нужные данные и занести их в таблицу.

Тогда 100 писем — около **100 минут ручной работы**.

Автоматический разбор такого объема занимает секунды. Даже с учетом загрузки и проверки результата экономия получается примерно **95–100 минут на 100 писем**.

Это оценка. Если бы было больше времени, я бы отдельно замерил ручную обработку 10 писем секундомером и использовал фактическое среднее время.

## Что изменится при 10 000 писем в день

При таком объеме текущую схему уже нужно перестраивать.

Основные проблемы:

- письма могут приходить большими пачками;
- одно письмо может случайно обработаться повторно;
- обработка по одному письму начнет упираться в скорость;
- таблица станет неудобным основным хранилищем;
- понадобятся повторные попытки при временных ошибках;
- нужно будет видеть ошибки, скорость обработки и стоимость.

Первым делом я бы разделил получение писем и их обработку через очередь:

`почта → очередь → обработчики → проверка → база данных → отчет`

После этого добавил бы:

- ID письма для защиты от дублей;
- 2–3 повторные попытки при временной ошибке;
- отдельную очередь для писем, которые так и не обработались;
- базу данных вместо таблицы как основное хранилище;
- мониторинг ошибок, скорости и стоимости;
- обычный код для простых полей, а AI — только для неоднозначных случаев.
